Через MCP (ae_do render.add_to_queue / set_output, render.duplicate_item) лише готуємо чергу й перевіряємо шляхи та тривалість. **За замовчуванням не викликаємо `render.start`** — користувач сам тисне Render у панелі Render Queue. Викликаємо його лише якщо користувач прямо наказав запустити рендер мені («запускай рендер»); тоді нагадати, що смуги прогресу в AE не буде.

**Робоча схема за замовчуванням (2026-10-01):** я роблю правки, виставляю робочу зону на видиму змінену частину ± 5 кадрів і кажу користувачу діапазон; він сам робить Duplicate with file name і пускає рендер. Сам запускаю рендер лише на пряму команду «зроби сам».

**Дозвіл на часткову перерендерку (2026-10-01), лише за командою «зроби сам»:** після того як користувач підтвердить внесення правок, я сам роблю дублікат пункту (`render.duplicate_item`, бо «Duplicate with file name» скриптом не викликається) і запускаю `render.start`, але лише після перевірки: `Work Area Only`, робоча зона = змінена частина ± 5 кадрів, правильна папка `finals\T<NN>\…`. Без явного підтвердження рендер не запускаю; після рендеру повертаю робочу зону на весь спот.

**Вимога перевірки місця (2026-10-01):** оскільки скрипт не виконує справжню «Duplicate with file name», перед `render.start` дубліката звіряю його вивід з оригінальним пунктом символ у символ (Full Flat Path/Base/Subfolder/File Name/Template), що папка існує й має кадри, `Use Comp Frame Number` true, `Skip Existing Files` false, і наперед рахую діапазон кадрів; після рендеру перевіряю, що нових файлів нема, а оновлено лише очікуваний діапазон. Якщо щось розходиться, не рендерю.

**Time Span (2026-10-01):** у пункті майстра завжди `Work Area Only`, не `Custom` (інакше «Duplicate with file name» рендерить весь спот, а не виділену частину). У `render.set_output` не передавати `timeSpanStart/Duration`. Поправки в споті: робоча зона = видима змінена частина ± 5 кадрів (0,2 с), рендерить користувач через Duplicate with file name; деталі в `references/render-prep.md`.

**Підтвердження (2026-10-01):** для спотів готую чергу так, як у W41B (див. `references/render-prep.md` скілу [[biedronka-spot-assembly-skill]]): Render тисне користувач. Якщо він прямо попросить запустити рендер, перед `render.start` перевіряю, що вивід іде в правильну папку `finals\T<NN>\…` (тиждень, частина, підпапка майстра, нема старих пунктів у черзі).

**Виняток (2026-09-30):** при переносі візок (`dmp`) в новий тиждень, коли всі пункти черги пишуть у сьогоднішній output (дата `YYYYMMDD` = сьогодні, новий тиждень у шляхах), користувач дозволив запускати `render.start` самому: це однокадрові PNG. Деталі в `references/carry-over.md` скілу [[biedronka-carry-over-wizki]]. Для довгих рендерів правило вище лишається.

**Why:** `render.start` виконується скриптом і блокує UI After Effects: у панелі немає паска прогресу, превʼю зникає, AE виглядає завислим (так було 2026-09-30 з END credits, ~20 хв). Користувач хоче в майбутньому спостерігати за рендером. Крім того, під час блокування він випадково натискав кнопки в AE.

**How to apply:**
- Перед постановкою в чергу: зберегти `_wip` (ae_save_project) і за дозволом записати його поверх vNN (`cp` через Bash, з перевіркою `cmp`).
- Тривалість задавати явно (`render.set_output` timeSpanStart/timeSpanDuration), не покладаючись на Work Area Only: робоча зона комп змінюється від випадкових натискань. Порівнювати з попереднім DI-файлом (mvhd-атом .mov; ffprobe і python на машині немає, читати через PowerShell).
- Дублікат пункту (`render.duplicate_item`) бере шлях за замовчуванням із чужого проєкту (Biedronka) — завжди перевіряти й виставляти outputPath; дублікат DONE-пункту не дозволяє змінити шлях. Надійніше `render.add_to_queue` з outputPath + `outputTemplate`.
- Після старту користувачем стежити за файлом (розмір/mtime) і повідомити через PushNotification, коли готово.
- DI-файли лежать у `X:/SyrenkaPicassa_230681/vfx/_out/credits/`; render змінених комп: start_credits (ProRes 4444 з альфою, 80.75 с) і END_credits (ProRes 422 HQ, 282 с).
